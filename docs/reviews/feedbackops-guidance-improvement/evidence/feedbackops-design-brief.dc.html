DESIGN BRIEF · 피드백 운영 루프 설계

FeedbackOps
설계 문서 브리프

FeedbackOps는 피드백 접수·분석·실행·결과 확인을 하나의 업무 흐름으로 묶되, VOC·Task·Survey를 강제로 합치지 않고 연결 기록과 검토 버퍼로 신뢰를 만든다. 결정권자에게 중요한 값은 더 많은 화면이 아니라 후속 누락 감소·backlog 보호·결정 근거 보존이다.

소스: FeedbackOps 로컬 설계 문서군. 현재 로컬 `develop`은 `origin/develop`보다 31커밋 앞선 상태다.

02 · SYSTEM MAP

시스템 지도 — 독립 시스템과 Integration Layer

03 · INVARIANTS

핵심 불변식 — 강제 변환 금지와 상태 분리

설계의 중심은 연결을 허용하되, 상태와 소유권을 섞지 않는 것이다. 편의 변환이 늘어나는 순간 audit trail과 reporter-facing 신뢰가 동시에 약해진다.

3.1Survey→VOC 자동 생성 금지
Survey Response는 Finding이나 Evidence가 될 수 있지만 새로운 VOC로 전환하지 않는다.
3.2VOC→Task 직접 생성 금지
VOC follow-up은 Task Request를 만들고, review 이후 Backlog Task로 전환된다.
3.3Task Done≠VOC 해결
Task 상태와 reporter-facing VOC Status는 별도 상태 머신이며 수동 확인이 필요하다.
3.4Dashboard=next action
모든 missing link가 아니라 정책상 기대되는 follow-up gap과 다음 조치를 보여준다.
NEVER
Survey Response→VOC, Task Done→VOC 해결, Project 기준 MVP scope, 편의 컬럼으로 cross-system history 복제.
ALLOW
VOC·Survey→Finding, Finding→Task Request, released work→status review candidate, Dashboard→policy-based gap queue.
04 · BOUNDARIES

도메인 모델 — 소유 경계와 표준 객체

소유 경계는 단순한 폴더 구분이 아니라 query·command·audit의 기준이다. 강한 소유관계는 직접 FK로 두고, 선택적 cross-system 관계는 `entity_links`로 둔다.

VOC System

VOC, VOC Cluster, Reporter-facing Status, Public Update 소유.

Finding

Finding, Evidence Highlight 소유. evidence를 실행 후보로 정리한다.

Task

Task Request, Task, Milestone, execution view 소유.

Survey

Survey, Survey Response, Survey Result 소유.

직접 FK 기준
Primary Managed System, Analytics Area, 강한 소유관계처럼 query·permission의 기본 축이 되는 값.
Entity Link 기준
optional, cross-system, many-to-many, evidence/support/follow-up처럼 관계 자체가 이력인 값.

07 · UI PRINCIPLES

UI 운영 원칙 — 빠른 리스트, 보존되는 맥락

FeedbackOps UI는 Linear처럼 빠르고 밀도 높은 운영 도구를 기본으로 하되, VOC는 triage·ownership·Reporter update 흐름을 보존한다.

List-first 운영

주요 객체는 List에서 스캔하고 Detail Panel에서 판독한다.

Contextual create

연결 객체 생성은 현재 맥락을 잃지 않는 위치에서 시작한다.

Separated status

내부 처리 상태와 reporter-facing 상태는 시각적으로 분리한다.

Triage use case
Unassigned·Untriaged·High Severity 같은 view에서 VOC를 빠르게 분류하고 후속 action을 고른다.
Execution use case
Task Requests는 Tasks에, Findings·Evidence·Coverage·Links는 Integration에 배치해 전환 맥락을 잃지 않는다.

08 · MVP PATH

MVP 경로 — 먼저 성공시킬 루프

첫 성공 흐름은 일반 사용자의 VOC 제출에서 시작해 triage, cluster, Finding, Task Request, Backlog Task, reporter-facing status update, Action Dashboard 추적으로 닫힌다.

ALPHA

Core·AD·Workspace, 기본 권한, VOC 등록·Triage·Inbox, Basic Task, Entity Link.

MVP

Finding, Task Request, VOC follow-up, Survey→Finding 경로, 유사 VOC, Action Dashboard.

LATER

workflow builder, full auto clustering, external integration, advanced BI는 MVP 밖에 둔다.
