# COMPOSITION GUIDE — 화면 밀도와 섹션 내 구성

> 이 문서는 *무엇을 쓰는가*(`authoring-guide.md`)와 *정확히 어떻게 보이는가*(`design.md`) 사이의 빈 중간 층을 채운다. 즉 **한 섹션(≈한 뷰포트)에 얼마를 담고, 그 안에서 요소를 어떻게 배열하는가**를 규정한다.
> 전제: 이 문서는 슬라이드 덱이 아니라 **위→아래로 읽는 종이**다. 아래의 "밴드/뷰포트" 규칙은 페이지 나눔이 아니라 **스크롤 리듬의 예산 단위**다 — 스크롤 문서에는 슬라이드 경계도, 작업기억 리셋도 없다.
>
> **This doc owns:** density budgets (섹션·뷰포트당 요소 상한), in-section composition/layout (배열·열 수·도해 배치), focal hierarchy (무게중심), whitespace/rhythm, viewport-level pacing (스크롤 전반의 밀도 교대).
> **This doc does NOT cover:** exact HEX/px token values → `design.md` (§3 spacing, §6 density); voice·skeleton·page-type content → `authoring-guide.md` (§1/§2/§4); 컨테이너·JS·런타임 → `../../core/runtime-spec.md`. 값은 여기서 재진술하지 않고 참조만 한다.

## 0. 단위 정의 (이 문서 전용)

| 단위 | 값 | 무엇을 세나 |
|------|-----|-----------|
| **밴드(band)** | 세로 ≈900px | 세로 예산 (섹션 높이·잉크 원소 총량) |
| **콘텐츠 폭(content width)** | ≈972px (sheet-pad 안쪽) | 폭 예산 (지배 요소 70%·도해 배치 임계) |
| **뷰포트(viewport)** | 한 화면 높이 (≈1밴드) | 동시 노출 예산 (한 화면에 같이 보이는 블록 수) |

두 상수(밴드 900 · 콘텐츠 폭 972)는 `design.md`의 `sheet-pad`/`lead-max`에서 파생된 것이며, 임의로 다른 값을 추정하지 않는다. **세로는 밴드로, 폭은 콘텐츠 폭으로 센다.**

- **의미 블록(meaning block)** = 최상위 컴포넌트 하나(리드 / 도해 패널 / 카드 그리드 / 표 / 콜아웃 세트). 카드 그리드 6장은 **의미 블록 1개**다.
- **잉크 원소(ink atom)** = 그 안의 원자(카드·노드·행·칩·바 하나). 카드 6장은 **원소 6개**다.
두 층을 혼동하지 않는다 — 밀도 예산은 이 두 층에 각각 걸린다(§2).

## 1. 원칙 (Principles)

**P1 — 한 섹션 = 한 논지 (One thesis per section).**
섹션은 리드 한 문장으로 요약된다. 요약에 "그리고"가 두 번 들어가면 섹션을 쪼갠다. 리드 문장 수는 섹션이 다루는 아이디어 수의 상한 신호다.

**P2 — Figure당 한 아이디어 (One idea per figure).**
하나의 도형/차트는 하나의 판독 과제만 준다. 두 축의 주장은 두 figure다. (`design.md §6.6`이 Data 페이지 한정으로 말한 규칙을 **전 타입으로 승격**한다.)

**P3 — 뷰포트당 무게중심 하나 (Single focal anchor, 2-tier).**
한 화면에서 시각적으로 가장 무거운 **블록**은 정확히 하나다. 그 블록이 열거형 그리드이면 *내부 항목*은 동급 무게로 두고 개별 강조를 하지 않는다. 동급 무게 그리드가 한 섹션에 둘 이상이면 하나를 서브섹션(N.M)으로 내리거나 다음 뷰포트로 분리한다. (동일 가중 그리드로 우선순위를 감추는 것은 `design.md §8.2` 안티패턴이다.)

**P4 — 정보 향(scent) 무결성.**
리드가 명시한 수(數) = figure가 인도하는 수. "다섯 원칙"이라 쓰고 카드 4장을 그리면 신뢰가 샌다. 리드가 약속한 것을 도해가 정확히 그 수만큼 정산한다.

**P5 — 리드는 진입 게이트, 도해는 착지점 (Text-gate → figure-landing).**
읽기 순서는 항상 `eyebrow → h2 → lead → [무게중심] → (보조)`. 도해는 리드보다 먼저 등장하지 않는다 — 리드를 읽고 시선을 내리면 바로 무게중심이 착지하도록 배치한다.

**P6 — 디바이스 다양성 예산 (Component-kind budget).**
한 섹션이 섞는 서로 다른 컴포넌트 *종류*는 ≤3. 4색 콜아웃을 한 그리드에 몰면 시맨틱 색이 장식이 된다.

**P7 — 데이터-잉크 절제 (Data-ink).**
값을 나르지 않는 픽셀은 삭제 후보다. 위치·길이·색이 이미 인코딩한 정보를 인바(in-bar) 텍스트로 재진술하지 않는다(간트·바 차트).

**P8 — 밀도는 역할의 함수 (Density follows role).**
cover 최저 → overview 낮음 → deep-dive/table 최고 → reference 압축·저강도. 밀도를 역할과 어긋나게 쓰면(overview에 3열 촘촘 그리드) 시스템이 무너진다.

**P9 — 여백은 예산이지 잔여가 아니다 (Whitespace as budget).**
블록 간 간격이 위계를 인코딩한다(인접 vs 구분 — `design.md §3.2`). 세 번째 블록을 넣고 싶으면 간격으로 다음 밴드로 밀거나 섹션을 쪼갠다.

## 2. 밀도 예산 (Density budgets)

### 2.1 전 타입 공통 상한

세 상한은 각각 다른 축(동시성 / 구조 / 총량)을 걸며 **모두 동시에 만족**해야 한다.

| 축 | 상한 | 근거 |
|----|------|------|
| **뷰포트당 동시 의미 블록** | ≤2 (한 화면에 같이 보이는 것) | 3개가 한 화면에 잡히면 간격을 `구분(distinct)`으로 벌려 최소 하나를 다음 밴드로 민다 |
| **섹션당 최상위 블록** (리드 제외) | ≤3, 권장 1–2 | deep-dive만 서브섹션 반복으로 예외 |
| **밴드당 잉크 원소** (카드+노드+행+칩) | ≤18 | 과밀 하드 실링 |
| **병렬 묶음당 항목** | 3–4 이상적, 절대 상한 7±2 | 5 초과 시 판독자는 세지 않고 "많다"로 뭉갠다. 7+ → 표로 승격 |
| **컴포넌트 종류** | ≤3 / 섹션 | P6 |
| **섹션 세로 높이** | 1.0–3.0밴드 | 2.5밴드에서 "분할 검토" 경고, **3.0밴드(≈2700px) 초과 시 강제 분할** — 서브섹션(N.M) 또는 act divider(`design.md §4.12`) |
| **뷰포트당 bold** | ≤5–6 (문단당 ≤1–2는 `authoring-guide §3` 유지) | 카드 6장×각 2 = 12개가 한 화면에 몰리는 것을 막는 화면 단위 상한 |

> **figure 개수:** 주 figure는 밴드당 1개, **섹션당 최대 2개**(서로 `구분` 간격으로 분리). 3번째 figure = 섹션 분할 신호.

### 2.2 페이지 타입별 배정

밀도 형용사("low/medium/high")는 `design.md §6`, 콘텐츠 패턴은 `authoring-guide §4`. 아래는 그 사이의 **정량 상한**이다.

| 페이지 타입 | 세로(밴드) | 아이디어 | 주 figure | 무게중심 형태 | 병렬 항목 상한 |
|-------------|:---:|:---:|:---:|---|---|
| Cover (§4.1) | 1.0 | 1 (thesis) | 0 | h1 | 스탯 타일 4 (flex, 3–5 수용·4 권장) |
| Overview (§4.2) | 1.0–1.5 | 1 | 0–1 | 리드 **또는** 단일 도해 | soft 카드 3–4 |
| Problem/Findings (§4.3) | 1.5–2.0 | 1 | 0 (열거는 도형 아님) | 균질 그리드 (무게중심 0 허용) | number-chip 카드 4–6, 2열×≤3행 |
| Direction (§4.4) | 2.0–3.0 | 1 | 1 (before/after **또는** process) | before/after 패널 (폭 ≥70%) | 컴포넌트 라인 ≤5 · 노드 ≤5 |
| Deep-dive (§4.5) | 2.0–3.0 | 1/서브섹션 | 서브섹션당 1 | 서브섹션당 도해 | 서브섹션 2–4 |
| Comparison (§4.7) | 1.5 | 1 | before/after 1 | before/after 패널 | 열당 pill 3 |
| Data (§4.6) | 1.0–1.5 | 1/figure | 1 (엄격) | 차트 1 | 계열 ≤8 |
| Roadmap (§4.9) | 1.5 | 1 | gantt 1 (§5.6) | gantt | 행 4–6 |
| Table (§4.7) | 1.5–2.0 | 1 | table 1 | 표 | 행 ≤7, 열 ≤4 |
| Reference (§4.10) | 1.0–1.5 | — | 0 | 없음 (균질 저강도) | 용어 6–10, 2열 |

## 3. 섹션 내 구성 (In-section composition)

### 3.1 수직 사다리 (기본형)

모든 본문 섹션은 단일 컬럼 수직 사다리로 읽힌다:

```
eyebrow → h2 → lead(≤760px) → [무게중심 블록] → (보조 블록)
```

- **eyebrow→h2→lead는 뷰포트 상단 1/3 안에** 다 들어온다(P5).
- **리드는 항상 단독 1블록**, `lead-max`(760) 고정 — 그리드 폭까지 늘리지 않는다. 리드가 도해보다 넓으면 초점이 텍스트로 샌다.
- 블록 간격은 `design.md §3.2`의 인접/구분 두 값으로만 준다. 서브섹션 경계·"다음 밴드로 밀어낼 블록" 앞에는 **구분 간격**을 쓴다.

### 3.2 도해 배치 결정 (두 형식만 허용)

| 조건 | 배치 |
|------|------|
| 기본 (모든 가로형·정사각) | **text top → figure below**, full-width |
| 도해 종횡비(세로:가로) **≥1.3 AND 폭 ≤480px** | text-left / figure-right `1fr 1fr`, `align-items:stretch`, 구분 간격 |

- **두 조건을 모두 만족할 때만** 좌우 분할한다. 하나만 만족하면 top→below.
- **가로로 넓은 도해(process-row · gantt · before/after · sequence)는 절대 좌우 분할하지 않는다** — 항상 full-width top→below.
- 그 외 임의 인터리빙 금지. 도해는 언제나 figure panel 안. (`authoring-guide §4.5` 재확인.)

### 3.3 카드 그리드 열 수 = 셀 본문 부피

열 수는 미학이 아니라 셀 본문 길이가 정한다. 한 그리드 안에서 열 수를 섞지 않는다.

| 셀 본문 | 열 수 | 셀 최소폭 |
|---------|:---:|:---:|
| ≤2줄 글로스 | 3열 | ≥300px |
| 1문단 (≤3문장) | 2열 | ≥440px |
| 긴 서술 / 상태행 | 1열 (세로 스택) | — |

- **텍스트 카드 4열 이상 금지** — 셀폭이 keep-all 줄바꿈이 깨지는 폭으로 떨어진다. **숫자 타일만 예외**(cover stat tiles · dark stat band · stat-card grid는 4열 허용, `design.md §4.11/§5.9`).
- **항목 5개는 2열로 내린다.** 3열에 넣으면 마지막 행이 "2+빈칸"이 되어 위계가 깨진다. 억지 6번째 카드로 채우지 않는다(P4 위반) — 우선순위는 ① 2열로 내림, ② takeaway chip으로 그리드를 닫음.
- **파리티:** 2·4·6 → 2열, 3·6 → 3열.

### 3.4 병렬성 & 한국어 행폭

- 한 행의 카드는 본문 길이 편차 **±1문장 이내**. 짧은 카드가 "덜 중요"로 오독되지 않게 한다(`authoring-guide §3` 병렬 규칙의 시각적 귀결).
- 카드 heading = 조사 없는 명사구(`authoring-guide §3.1`). 카드끼리 문법 형태를 맞춘다.
- **카드 본문 한 행 ≈16–24자(어절 6–9개)** 를 넘기지 않는다 — `keep-all`에서 어절이 길면 큰 rag이 생겨 다음 행 시작을 잃는다.
- **밀도 이중화:** 스캔 영역(칩·노드·바 라벨)은 개조식으로 가볍게, 정독 영역(리드·카드 본문)은 `~한다` 문어체로. 리드에 bold를 3개 나열하지 말고, 열거는 아래 개조식 칩/노드로 내려 스캔 부하와 정독 부하를 분리한다.

### 3.5 마감 요소

카드 그리드(4개 이상)는 하단에 한 줄 종합 **takeaway chip**(`design.md §4.6` 계열)으로 닫아, 스캔이 열린 채 끝나지 않게 한다. 섹션당 1개.

## 4. 무게중심과 여백 (Focal hierarchy & whitespace)

### 4.1 무게중심 규칙 (조건부 위계)

무게중심의 **형태**는 페이지 타입의 함수다. 상한은 언제나 **블록 하나**(2개 금지).

- **위계형(argumentative/figure): direction · comparison · data · deep-dive · roadmap** → 무게중심 **1개 필수**. 지배 요소가 **콘텐츠 폭의 ≥70%**를 점유한다. before/after·gantt·process-row는 full-width(100%)가 기본. 지배 요소 없이 동급 그리드만 있으면 결함(§6 07 사례).
- **열거형(enumerative): problem · findings · reference** → 무게중심 **0 허용**. 균질 peer 그리드 자체가 무게중심이며, 한 카드만 강조하면 "가짜 위계"다. **단, 그리드는 반드시 리드 또는 마감 칩으로 프레이밍**되어 "무프레임 카드 벽"이 아니어야 한다.
- **cover/overview** → h1 / lead 문단이 무게중심.

> 판정 순서: 타입이 위계형인데 지배 요소가 없으면 결함. 열거형인데 한 카드만 강조해도 결함. **둘 다 잡는다.**

### 4.2 지배 요소의 시각 지분

- 지배 요소는 폭 ≥70% + **리드 직후 첫 스크린 하단에 착지**(P5).
- 부차 요소(트리 리프 칩·범례·각주)가 지배 요소보다 시각 지분을 더 먹으면 잉크 예산 낭비다 — muted 한 줄로 접거나 뺀다.
- **스탯 밴드/다크 카드는 문서당 ≤2–3회.** 매 섹션 등장하면 무게중심 신호가 인플레되어 아무것도 무겁지 않게 된다.

### 4.3 콜아웃은 aside 전용 (역할 게이트가 배치보다 우선)

콜아웃(`design.md §4.8`)은 **부차 논평(aside)에만** 쓴다. 판정은 배치보다 **역할이 먼저**다:

1. 이것이 진짜 aside인가? — *일차 콘텐츠*(핵심 불변식·peer 진술)라면 콜아웃이 아니라 균질 카드 그리드/리스트다.
2. 통과했으면 배치: **≤2/밴드**, 그리고 **색 변형(KEY/NOTE/WARN/OK)을 한 그리드에 3개 이상 동시 사용 금지** — 시맨틱 색은 청크 구분자가 아니라 *역할 신호*다. 4색을 나란히 놓으면 장식으로 전락한다.

### 4.4 여백을 예산으로

- 측정 불가능한 "잉크 커버리지 %"는 강제하지 않는다 — 대신 측정 가능한 대리 지표로 강제한다: **의미 블록 ≤2/뷰포트 · 잉크 원소 ≤18/밴드**.
- 통짜 회색 벽(고밀도 문단 연속)은 스캔 진입점을 없앤다. 리드·칩·도해로 진입점을 심는다.

## 5. 스크롤 전반의 페이싱 (Viewport pacing)

- **밀/소 교대:** 연속 고밀도 섹션(deep-dive/table)은 **최대 2개**. 세 번째 고밀도 섹션 앞에 **브리더**(pull quote `§4.10` · dark stat band `§4.11` · divider `§4.12`)를 강제 삽입한다.
- **9섹션 초과 문서**는 3–4섹션마다 act divider로 막을 끊어 "얼마나 남았나"의 불안을 없앤다(`authoring-guide §2`).
- **1.0밴드 미만 본문 섹션**(리드만 있고 도해 없음)은 cover/divider/reference에서만 허용 — 본문이 반 화면이면 앞뒤와 병합한다.
- 밀도 배치가 역할과 맞물리는지 확인한다(P8): cover(저) → overview(저–중) → problem(중) → direction(중–고) → deep-dive(고) → … → reference(저강도 마감).

## 6. 밀도·구성 체크리스트

`authoring-guide §6`(내용/보이스)와 `design.md §9`(시각 재현)에 더해 실행한다.

1. [ ] **섹션 세로 1.0–3.0밴드.** 2.5 초과면 분할 검토, 3.0(≈2700px) 초과면 서브섹션/divider로 강제 분할.
2. [ ] **뷰포트당 동시 의미 블록 ≤2**, 섹션당 최상위 블록 ≤3(권장 1–2). 3번째는 구분 간격으로 다음 밴드로.
3. [ ] **밴드당 잉크 원소 ≤18**, 병렬 묶음 ≤6(7+는 표로).
4. [ ] **컴포넌트 종류 ≤3/섹션.**
5. [ ] **무게중심:** 위계형은 지배 요소 1개(폭 ≥70%, 리드 직후 착지) · 열거형은 균질 그리드 + 리드/칩 프레이밍. **동급 그리드 2개 금지.**
6. [ ] **정보 향:** 리드가 명시한 수 = figure가 인도하는 수.
7. [ ] **주 figure ≤2/섹션**, figure당 아이디어 1개.
8. [ ] **도해 배치:** 기본 top→below 단일 컬럼. 좌우 `1fr 1fr`은 종횡비 ≥1.3 **AND** 폭 ≤480px일 때만. 가로형(process/gantt/before-after)은 좌우 분할 금지.
9. [ ] **카드 열 수 = 본문 부피** (3열 글로스 / 2열 문단 / 1열 서술). 5개는 2열. 텍스트 카드 4열 금지(숫자 타일만 예외).
10. [ ] **카드 본문 한 행 16–24자**, 병렬 카드 길이 편차 ±1문장.
11. [ ] **콜아웃은 aside만** — 역할 먼저 판정, 색 변형 3+ 동시 그리드 금지, ≤2/밴드.
12. [ ] **뷰포트당 bold ≤5–6.**
13. [ ] **인코딩 중복 없음** — 위치/길이/색이 나른 정보를 인바 텍스트로 재진술하지 않는다.
14. [ ] **페이싱:** 연속 고밀도 ≤2섹션, 3번째 전 브리더. 스탯밴드/다크카드 문서당 ≤2–3회.

## 7. 워크드 비평 — FeedbackOps 예제 (do/don't)

`../../examples/feedbackops.dc.html`를 이 가이드로 읽는다. 밴드 예산은 대체로 잘 지켜 **과밀 섹션은 드물다** — 결함은 밀도가 아니라 **무게중심·향 무결성·역할 오용**에 몰린다.

### 잘한 것 (DO)

- **02 문제 — before/after 무게중심.** AS-IS를 dashed monolith로 묶고 TO-BE를 elevated key-node로 띄운 대비가 full-width 지배 요소 하나로 선다. 좌우 pill을 각 2개로 절제해 청킹 상한도 지켰다. → **위계형 섹션은 이렇게 지배 요소 하나가 폭을 잡는다.**
- **03 방향 — 5단계 process-row + 단일 takeaway 칩.** 선형 아이디어 하나를 한 figure로, 마지막만 green ✓로 종결하고 한 칩으로 닫았다. → **지배1 + 보조1의 이상적 예산(§2, §3.5).**
- **08 범위 — gantt 단일 초점.** figure당 한 아이디어(P2)의 모범, 주변 텍스트 최소.
- **reference — 2열 저강도 마감.** 밀도-역할 매칭(P8)이 정확하다.

### 고칠 것 (DON'T → FIX)

- **06 신뢰 — 콜아웃 4변형 동시 사용 + 과밀.**
  *증상:* KEY·NOTE·WARN·OK를 한 그리드에 4장 배치. 게다가 이들은 aside가 아니라 *핵심 불변식(일차 콘텐츠)*이고, 그 아래 표까지 와 의미 블록 3개가 한 대역에서 경쟁한다.
  *진단:* 역할/형식 불일치(§4.3) + 색의 장식화 + 뷰포트 블록 초과(§2.1). 배치가 2×2로 깔끔한 것은 사실이나 **예쁜 배치가 역할 오용을 정당화하지 않는다.**
  *FIX:* 4개를 **단일 변형의 균질 카드 그리드**로 통일(peer 진술이므로 색은 하나). 표는 구분 간격으로 다음 밴드로 밀거나 별도 07-table 섹션으로 승격. 콜아웃은 진짜 aside 1–2개만.

- **05 트리아지 — 향(scent) 불일치 + 리드 정독 과부하.**
  *증상:* 리드가 "세 상태 기계"를 bold 3개로 나열하고 약속하나, 도형은 Reporter 대면 상태 하나만 그린다.
  *진단:* P4 위반(약속 3, 인도 1) + 문단당 bold 상한 초과(§2.1).
  *FIX:* 3-레인 비교(작은 상태 다이어그램 3개 나란히)로 약속한 3을 모두 인도하거나, 리드를 "하나를 예시로"로 조정. 세 이름은 리드 bold가 아니라 아래 개조식 칩/노드로 내린다(§3.4).

- **07 원칙 — 수 불일치 + 초점 부재.**
  *증상:* 리드 "다섯 전략 원칙"인데 카드는 4장. 게다가 원칙 카드(2열)와 Do/Don't(2열)가 둘 다 동급 무게로 와 지배 요소가 없다.
  *진단:* P4 위반 + 동급 그리드 2개(§4.1).
  *FIX:* 5번째 카드 추가 또는 "네 원칙"으로 수 정합. 원칙 카드를 무게중심으로 두고 Do/Don't는 서브섹션(N.M)으로 구분 간격 분리.

- **04 도메인 — 최상위 블록 초과 + 초점 이중화.**
  *증상:* tree 도해 + h3 + 3열 카드 사슬로 최상위 블록 4개. tree와 카드 그리드가 둘 다 중간 무게라 "무엇을 먼저 보나"가 모호하고, tree 리프 칩(권한·리포트 그룹·대시보드)이 논지에 부차적인데 시각 지분을 먹는다.
  *진단:* 섹션 블록 ≤3 초과(§2.1) + 무게중심 이중화(§4.1) + 부차 요소 지분 과다(§4.2).
  *FIX:* tree를 04, 레코드 사슬 카드를 별도 서브섹션으로 분리. 리프 칩은 muted 한 줄로 접는다. 04 카드는 본문이 길므로 3열이 아니라 **2열**이 맞다(§3.3).

- **08 간트 — 인코딩 이중화(경미).**
  *증상:* 인바 라벨 + 색 + 하단 3-범례로 색 의미를 두 번 인코딩.
  *진단:* P7 위반. 간트는 위치·길이가 이미 시기·범위를 나른다.
  *FIX:* 범례가 색을 정의하면 인바 텍스트는 제거한다.

> 종합 do/don't: **무게중심 처리(02·03)는 모범**, **한 섹션의 블록 수(06)·부차 요소 지분(04·08)·향 무결성(05·07)**은 이 가이드의 상한을 넘는다. 위계형이면 지배 요소 하나로, 열거형이면 균질 그리드 + 프레임으로, 그리고 **리드가 약속한 수를 도해가 정확히 갚는다.**
