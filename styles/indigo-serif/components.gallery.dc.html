계층 아키텍처 맵 — 레이어·모듈·연결 layer-map shape: layered-structure

기본 콘텐츠

번호 카드 그리드 — 동급 항목 나열 card-grid shape: peer-list
언제 쓰나서로 동등한 항목 3–6개를 나열한다: 문제점, 발견 사항, 원칙, 리스크(등급 없음), 요구사항. 항목 사이에 순서·흐름·관계가 없다. · 쓰지 않을 때: 항목 사이에 순서가 있다 → process-row. 관계·연결이 있다 → er-relations/layer-map. 행과 열이 모두 의미가 있다 → table/matrix. 이미 도식이 있는 섹션에 "더 자세히"를 덧붙이는 용도로 쓰지 않는다.
2.1흩어진 접수 경로
VOC와 설문 응답이 서로 다른 화면에서 들어와 중복·유사 판단이 개인 기억에 의존한다.
2.2설명되지 않는 실행
Task가 왜 시작되었는지, 어떤 근거가 있었는지 추적하기 어렵다.
2.3닫히지 않는 검증
Task 완료가 곧 사용자 문제 해결을 뜻하지 않아 결과 확인이 빠진다.
연결 누락
링크가 없으면 후속 공백이 보이지 않는다.
→ 정책 기반 recovery 큐로 노출한다.
→ 세 문제 모두 '연결이 기록되지 않는다'는 한 지점에서 출발한다.
콜아웃 — 핵심·권장·주의·참고 한 줄 callout
언제 쓰나본문 흐름 밖의 한 문장(aside): 꼭 기억할 핵심(KEY), 권장 방식(OK), 주의·금지(WARN), 낮은 우선순위 참고(NOTE). · 쓰지 않을 때: 섹션의 주 내용 → 도식이나 card-grid. 여러 개를 나란히 → 쓰지 않는다(밴드당 최대 2개, 서로 다른 변형 3개 이상 동시 금지).
핵심연결 이력의 정본은 entity_links 하나다.
권장단일 VOC 조치가 명확하면 Finding 없이 Task Request로 간다.
주의Task 완료 상태를 VOC 해결 상태로 자동 연동하지 않는다.
참고Evidence 전용 화면은 다음 단계에서 다룬다.
표 — 행과 열 모두 의미가 있는 문장 비교 table shape: text-table
언제 쓰나행(항목)과 열(관점) 모두 의미가 있고 칸마다 짧은 문장이 들어간다. 문제↔해결↔효과 대응, 미정 질문(항목 / 현재 방향 / 결정 필요), 용어 대응. · 쓰지 않을 때: 칸이 ✓/✕ → matrix. 조건 조합 → decision-table. 열이 하나뿐 → card-grid.
