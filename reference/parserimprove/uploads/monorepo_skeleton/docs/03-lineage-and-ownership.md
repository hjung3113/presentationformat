# 03. 흐름(Lineage)과 소유(Ownership)

*owner: TBD · status: draft · last-updated: 2026-07-01*

> 이 문서가 데이터/컴포넌트 흐름 예시의 **단일 정본**이다. 다른 문서는 여기를 참조한다.

## Ownership 원칙

1. 모든 계약(표준 로그 스펙·기준정보·진행상태·골든세트)은 owner를 가진다.
2. 모든 컴포넌트는 owner를 가진다.
3. 각 컴포넌트는 자신이 읽는 계약과 쓰는 산출을 명시한다.
4. 계약 breaking 변경은 영향 컴포넌트 owner가 확인한다. (경량 — 다팀 승인 절차 아님)

## 흐름 모델 (설비 팬아웃)

> ⚠️ dataset producer→consumer DAG가 아니다. 동일 파이프라인을 **수천 설비에 대해 반복**하는 팬아웃이다.

```txt
[설비 N개] 각각에 대해:
  수집기 ──원본──> (비표준) 컨버터 ──표준화──> 표준파서 ──> 공정 DB
                                                          └─ 진행상태(SSOT) 갱신
스케줄러: 설비별 진행상태를 읽고 → 시나리오 결정 → probe/collect → 가공 지시
Config파서: 설정 파일 ──> 공정 DB (별도 경로)
```

## 컴포넌트 ↔ 계약 관계

| 컴포넌트 | 읽는 계약 | 쓰는 산출 |
|----------|-----------|-----------|
| 스케줄러 | 진행상태(SSOT) | 진행상태 갱신 |
| 수집기 | (경로 규약) | 원본 파일 + 가용성 |
| 컨버터 | 표준 로그 스펙 | 표준형 파일 |
| 표준파서 | 표준 로그 스펙·기준정보·정규화/보정 규칙 | DB 결과 + 진행상태 |
| Config파서 | (설정 포맷) | DB 결과 |

## 문제로 간주하는 상태

- owner 없는 계약/컴포넌트
- 진행상태(SSOT)를 두 곳에서 쓰기 (DB 외 소켓/파일이 진실 행세)
- 표준 로그 스펙에 없는 컬럼을 코드가 생성
- carryover 경계가 계약에 정의되지 않은 채 코드에만 존재
- 골든 세트 없이 가공 로직 변경

## 자동 생성 (고도화)

컴포넌트↔계약 관계도는 수동보다 도구 생성 권장. (기준: 각 컴포넌트 README의 읽는/쓰는 계약 선언) — `tools/` 참조, 단 MVP 필수 아님.
