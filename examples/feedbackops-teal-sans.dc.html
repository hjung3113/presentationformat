01 · OVERVIEW

제품 개요 — 피드백이 업무가 되는 인박스

FeedbackOps는 제출된 VOC·설문 결과·Finding·실행 작업·결과 검증을 하나의 경직된 워크플로에 밀어 넣지 않고 연결하는, 내부 AD 인증 운영 시스템이다. 모든 화면은 알려진 Managed System 범위 안에서 일하는 인증된 내부 Actor를 위한다. 사용 맥락은 탐색이 아니라 운영이다 — VOC가 도착했거나, 트리아지 큐가 쌓였거나, Finding에 증거가 필요할 때 연다.

운영 중심
세션은 짧고 밀도 높고 결정 지향이다. 둘러보는 곳이 아니라, 결정을 내리러 오는 곳이다.
단일 Workspace
모든 도메인 레코드는 정확히 하나의 Workspace에 속한다. MVP에서 교차-Workspace 링크는 없다.
궤적이 일급
"들은 것 → 한 것"의 궤적을 손으로 재구성하지 않는다. entity_links가 그 궤적을 일급으로 만든다.
02 · PROBLEM

문제 — 흩어진 도구, 손으로 잇는 궤적

FeedbackOps가 없으면 인테이크·트리아지 결정·증거 수집·실행 추적·결과 검증이 각각 다른 도구에 흩어져 산다. 그 사이의 궤적은 사람이 손으로 재구성한다. 아래는 현재(AS-IS)와 목표(TO-BE)의 대비다.

03 · DIRECTION

방향 — 루프를 닫는 다섯 단계

FeedbackOps는 인테이크에서 문서화된 결과까지의 루프를 닫는다. 궤적을 entity_links로 일급화하고, 트리아지 결정을 감사 가능하게 만들며, 교차-시스템 이력을 우연이 아니라 정본으로 만든다.

04 · DOMAIN

도메인 모델 — 하나의 범위, 느슨한 링크

모든 레코드는 정확히 하나의 Workspace와, VOC·Finding·Task·Survey의 경우 하나의 Primary Managed System을 지닌다. 다중 시스템 영향은 소유가 아니라 링크로 표현한다. 아래는 범위 계층이다.

05 · TRIAGE

트리아지 — 분리된 상태 기계

세 상태는 서로 다른 상태 기계이며 자동 교차-매핑이 없다 — VOC 트리아지 상태, Reporter 대면 VOC 상태, Task 상태. Reporter가 보는 진행과 내부 실행 상태를 시각적으로도 구조적으로도 분리하는 것이 제품 불변식이다.

Severity심각도
트리아지에서 지정하는 운영 영향 수준. 문제가 얼마나 심각한지를 뜻하며, 일하는 순서가 아니다. Reporter가 아니라 Developer·Admin이 정한다.
Priority우선순위
Finding·Task가 계획에서 나르는 실행 순서 신호. 트리아지 이후 결정되며 Severity와 구별된다. Reporter에게 노출되지 않는다.
06 · TRUST

신뢰 — 영수증으로 얻는 확신

확신은 장식이 아니라 영수증에서 온다. 모든 상태 변화는 보이고, 모든 교차-시스템 링크는 entity_links로 추적되며, 모든 Reporter 대면 메시지는 모든 내부 노트와 물리적으로 분리된다.

교차 이력의 정본
교차-시스템 이력은 편의 컬럼이 아니라 entity_links로 정본화된다.
분리된 세 작성기
Public Update·Reporter Reply·Internal Comment은 물리적으로 분리된 세 서피스다.
빈 실패 대신 요청 경로
권한 제한 콘텐츠는 스택 트레이스가 아니라 승인 요약 또는 요청 경로를 보여준다.
감사 가능한 전이
UI의 모든 가시적 상태 변화는 감사 가능한 백엔드 전이로 매핑된다.

07 · DESIGN

디자인 원칙 — 프로토타입이 곧 스펙

디자인은 제품을 위한다. 디자인이 제품이 아니다. 다섯째 원칙 '영수증에 의한 신뢰'는 06에서 다뤘고, 나머지 네 실행 원칙이 화면을 지배한다.

7.1라이트 토큰만
시맨틱 토큰만 소비한다. 기능 화면의 원시 hex·스케일 밖 px는 리뷰 차단 사유다.
7.2세 개의 쉘
PageShell·ListShell·WorkbenchShell 그리고 그 외엔 없다. 네 번째 쉘은 ADR 개정을 요한다.
7.3프로토타입이 스펙
1px 이내로 미러링하고 발명하지 않는다. 프로토타입이 침묵하면 채우지 말고 멈춰 묻는다.
7.4픽셀 디프 베이스라인
페이지마다 Playwright 픽셀 디프, 프로토타입 99% 이상 일치 목표. HIGH·카피 불일치는 머지 차단.

Do / Don't

✓시맨틱 토큰 소비, 프로토타입 미러링
✓Reporter 대면·내부 서피스 물리적 분리
✓밀도 높은 리스트-우선 운영 화면
✕원시 hex·스케일 밖 px, 임의 발명
✕마케팅 그라데이션·글래스모피즘·다크 기본
✕동일 가중치 카드 그리드로 우선순위 은폐

용어

VOC — 내부 Actor가 직접 제출한 목소리 항목. 설문 응답·Task·Finding 아님.
Finding — 한 Managed System의 문제·패턴·실행 후보를 요약한 증거 기반 판단.
Task Request — 검토된 실행 후보. 백로그를 미검토 실행으로부터 보호.
Entity Link — 두 레코드 간 타입 있는 느슨한 관계. relation_type + visibility 보유.
Managed System — FeedbackOps가 피드백·개선을 추적하는 내부 회사 시스템 (예: Tableau).
Reporter — 특정 VOC를 제출한 Actor. 독립 역할이 아니라 역할 모양.
Severity vs Priority — 문제의 심각도 vs 실행의 순서. 별개 결정.
Reporter Summary — Reporter에게 보이는 공개 안전 요약. 내부 상세 노출 금지.
