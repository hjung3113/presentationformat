# 컨버터 (Converter) 설계 문서

> 작성 목적: 「반도체 설비 이벤트 로그파서 개선 프로젝트」의 책임 분리 구조 중 **컨버터** 컴포넌트를 아키텍처 레벨로 정의한다.
>
> 근거: 상위 문서 `parser_project_revised.md`(3.1④, 3.1 비표준 처리 흐름, 9장), 짝 문서 `file_collector_design.md`·`scheduler_design.md`·`integration_contracts_design.md`. 충돌 시 상위 문서 우선.
>
> ⚠️ **본 문서는 아키텍처·계약 레벨의 골격이다. 세부 구현(클래스·필드·알고리즘)은 확정되지 않았고 변경될 수 있어 의도적으로 생략한다.**

---

## 0. 한 줄 정의

> **컨버터는 비표준 로그를 회사 표준 로그 스펙 형식으로 "변환(형식 맞추기)"하는 컴포넌트다. 값 정규화·보정·start/end 병합은 하지 않는다 — 그것은 표준 로그 파서의 책임이다.**

컨버터의 산출물은 표준 로그 파서가 표준 로그와 **똑같이** 다룰 수 있는 형식이어야 한다. 이로써 "모든 가공을 표준 로그 파서 하나로 일원화"한다.

---

## 1. 배경

- 기존 비표준 로그 파서는 인수인계 미흡·저품질 레거시다(상위 문서 2.2).
- 설비사마다 로그 양식이 달라 각각 변환 로직이 필요하다(상위 문서 용어: 비표준 로그).
- 목표: 좋은 품질의 컨버터로 새로 만들어, 비표준도 컨버터를 거쳐 표준 형식이 되면 **동일한 표준 파서**로 처리한다(파서 일원화).

비표준 처리 흐름:

```mermaid
flowchart LR
    A[파일 수집기<br/>수집] --> B[컨버터<br/>표준 로그로 변환] --> C[표준 로그 파서<br/>정규화·보정·가공]
```

---

## 2. 책임 경계

### 2.1 하는 일 (In Scope)

| 책임 | 설명 |
|------|------|
| **형식 변환** | 설비사·모델별 비표준 양식을 표준 로그 스펙(TSV) 형식으로 맞춘다. |
| **설비사/모델별 변환 선택** | 입력 원본의 설비/모델/메이커에 맞는 변환 로직을 선택·적용한다. |
| **표준 스펙 준수 산출** | 산출물이 표준 로그 스펙(컬럼·구분자·인코딩 등)을 만족하도록 보장한다. |

### 2.2 하지 않는 일 (Out of Scope)

| 비책임 | 누가 | 이유 |
|--------|------|------|
| 값 정규화·보정 | 표준 로그 파서 | 정규화·보정은 표준/비표준 공통이므로 파서로 일원화(상위 문서 3.1③). 컨버터가 하면 로직이 다시 분산됨. |
| start/end 병합·흐름 추적·carryover | 표준 로그 파서 | 가공 단계. |
| 원본 수집·존재 확인 | 수집기 | |
| 시나리오 판단(live/rework/따라잡기) | 스케줄러 | 컨버터는 "주어진 입력을 변환"만 함(시나리오 불가지). |

> **경계 핵심**: 컨버터의 출력은 "표준 스펙 형식이지만 아직 정규화·보정 전"인 로그다. "형식은 표준, 값은 아직 원상태"가 정확한 산출 정의.

---

## 3. 설계 원칙

1. **형식 변환만(Transform-only)**: 값의 의미를 고치지 않는다. 표현 형식만 표준에 맞춘다.
2. **설비사/모델별 어댑터 구조(개념)**: 공통 파이프라인 + 설비사·모델별 변환 어댑터로 나눠, 신규 설비사 추가 시 어댑터만 추가한다. (구현 형태는 미정)
3. **시나리오 불가지**: live/rework 개념이 코드에 등장하지 않는다.
4. **테스트 가능 구조**: 처음부터 작은 함수·의존성 주입. 골든테스트로 산출 동등성 검증.
5. **멱등성**: 같은 입력 → 같은 표준형 출력.

---

## 4. 입출력 (계약 레벨)

| 구분 | 내용 | 계약 |
|------|------|------|
| **입력** | 비표준 원본 파일(수집기가 확보), 설비/모델/메이커 식별 | 경로·네이밍 규약(`integration_contracts_design.md` §2②) |
| **출력** | 표준 로그 스펙 형식의 파일(TSV) | 표준 로그 스펙(`contracts/log-specs/`, 단일 소스) |
| **의존 계약** | 변환에 필요한 매핑이 있으면 기준정보 참조 | `contracts/reference-data/` |

- 산출물 위치·네이밍은 표준 파서가 표준 로그와 동일 규칙으로 찾도록 통일.
- 언어: **.NET**. 표준 파서와 파일 기반으로 핸드오프(객체 직접 전달 아님).

---

## 5. 내부 구조 (개념 골격)

```mermaid
flowchart LR
    IN[비표준 원본] --> DET[설비사/모델 판별]
    DET --> ADP[해당 어댑터로 형식 변환]
    ADP --> VAL[표준 스펙 형식 검증]
    VAL --> OUT[표준형 TSV]
```

- **어댑터**: 설비사·모델별 변환 규칙 단위. 신규 설비사 = 어댑터 추가.
- **형식 검증**: 산출이 표준 스펙(컬럼·구분자·인코딩)을 만족하는지 확인 후 노출.
- (세부 어댑터 인터페이스·규칙 표현은 구현 시 확정 — 본 문서 범위 밖)

---

## 6. 테스트

- **골든 파일(동등성) 테스트**: 실제 비표준 로그 → 컨버터 출력 vs 기대 표준형. (`contracts/golden/`)
- 설비사·모델별 어댑터는 (입력, 기대 표준형) 쌍의 데이터 기반 테스트.

---

## 7. 범위 및 단계 계획

- **올해 (MVP)**: 신규 핵심. "비표준 → 표준화" 경로를 실제 데이터로 끝까지 동작시키는 것이 목표(상위 문서 9.1). 대상 설비사/모델 범위는 MVP에서 좁게 시작.
- **차후**: 어댑터 커버리지 확대, 레거시 비표준 파서 완전 대체.

---

## 8. 미정 사항

| 항목 | 비고 |
|------|------|
| 어댑터 인터페이스·규칙 표현 방식 | 구현 시 확정 (본 문서는 개념만) |
| MVP 대상 설비사/모델 범위 | 우선순위 결정 필요 |
| 변환에 기준정보가 필요한 범위 | reference-data 의존 여부 확정 |
| 표준 스펙 형식 검증 실패 처리 | 에러 코드 체계(`integration_contracts_design.md` §4.5)와 연동 |

---

> *세부 구현은 변경 가능성이 크므로 확정 후 반영한다. 표준 로그 스펙이 확정되면 4·5장의 산출 정의를 실제 스펙과 정합화한다.*
