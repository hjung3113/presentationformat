01 · OVERVIEW

정의·배경 — 파서 일원화의 앞단

설비사마다 로그 양식이 달라, 비표준 로그를 활용하려면 각각 변환 로직이 필요하다. 컨버터는 이 비표준 로그를 표준 로그 스펙 형식으로 바꿔, 표준 로그 파서가 표준 로그와 똑같이 다룰 수 있게 한다. 기존 비표준 파서는 레거시라, 좋은 품질의 컨버터로 새로 만들어 장기적으로 파서를 하나로 일원화한다.

02 · SCOPE

책임 경계 — 형식 변환만

컨버터의 경계는 날카롭다. 값의 의미를 고치지 않고 표현 형식만 표준에 맞춘다. 정규화·보정·병합은 표준/비표준 공통이라 표준 파서로 일원화하며, 컨버터가 손대면 로직이 다시 분산된다.

●하는 일 (In-Scope)
· 형식 변환 — 설비사·모델별 비표준 양식을 표준 로그 스펙(TSV)으로 맞춤
· 변환 선택 — 원본의 설비/모델/메이커에 맞는 변환 로직 적용
· 스펙 준수 산출 — 컬럼·구분자·인코딩이 표준 스펙을 만족하도록 보장
○하지 않는 일 (Out-of-Scope)
값 정규화·보정 → 표준 로그 파서
start/end 병합·carryover → 표준 로그 파서
원본 수집·존재 확인 → 파일 수집기
시나리오 판단(live/rework) → 스케줄러
→ 산출물 정의: "형식은 표준, 값은 아직 원상태" — out-of-scope는 '못 하는 것'이 아니라 다른 컴포넌트의 몫이다.
03 · PRINCIPLES

설계 원칙 — 네 가지

컨버터가 지켜야 할 원칙은 네 가지다. 모두 "형식만 바꾸고, 시나리오는 모른다"는 경계에서 파생된다.

01형식 변환만
값의 의미를 고치지 않는다. 표현 형식만 표준에 맞춘다.
02어댑터 구조
공통 파이프라인 + 설비사·모델별 변환 어댑터. 신규 설비사는 어댑터만 추가한다.
03시나리오 불가지
live/rework 개념이 코드에 등장하지 않는다. 주어진 입력을 변환할 뿐이다.
04멱등·테스트 가능
같은 입력 → 같은 표준형 출력. 작은 함수·의존성 주입으로 골든테스트 가능하게.

06 · SCOPE & TESTS

테스트·범위 — MVP와 차후

검증의 핵심은 골든 파일 동등성 테스트다. 실제 비표준 로그를 넣어 컨버터 출력과 기대 표준형을 diff한다. 올해는 신규 핵심 경로를 좁게 시작한다.

용어

표준 로그 스펙 — 회사 내부 표준 로그 양식. TSV(txt). 컨버터 산출의 목표 형식.
어댑터 — 설비사·모델별 변환 규칙 단위. 신규 설비사 = 어댑터 추가.
값 정규화·보정 — 제각각 표현 정렬 + 결함 메움. 컨버터가 아닌 표준 파서 책임.
골든 파일 테스트 — 실제 입력에 대해 출력을 기대값과 diff해 의도치 않은 차이를 검출.

* 본 문서는 아키텍처 골격이며, 표준 로그 스펙이 확정되면 산출 정의를 실제 스펙과 정합화한다. — 스펙 확장 팩(spec_extensions.md)의 컴포넌트 문서 arc·책임경계 컴포넌트를 적용한 파일럿.
